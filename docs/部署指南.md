# 部署指南

目标：把「小蜗 · 比奇堡租房」放到一台公网服务器上，得到一个能发给别人点开的链接。

整套服务由三个容器组成，`docker compose` 一条命令拉起：

```
web    Node 22 + Express，同时托管前端 dist/（对外 3001，映射到宿主 8080）
db     MySQL 8.0（数据存在 dbdata 卷里）
cache  Redis 7（可选增强，挂了会自动降级到数据库）
```

---

## 0. 先本地跑通（强烈建议）

部署失败时最难分辨的是「代码问题」还是「环境问题」，先在本地确认镜像能跑：

```bash
cp .env.production.example .env      # Windows: copy .env.production.example .env
# 打开 .env，把两个「请换成随机串」改掉；VITE_AMAP_KEY 填自己的高德 Key
docker compose up -d --build
docker compose ps                     # 三个服务都应该是 healthy
curl http://127.0.0.1:8080/api/health
```

浏览器打开 <http://127.0.0.1:8080>，能看到首页、地图、法拍房就说明镜像没问题。

> 首次启动会自动建表并写入演示数据（14 套房源 / 4 场拍卖 / 8 条帖子）。
> 想清空重来：`docker compose down -v`（**会连同数据卷一起删**）。

## 1. 准备服务器

| 项 | 建议 |
| --- | --- |
| 配置 | 2 核 2G 起（MySQL 约占 300MB，Node + Redis 很轻） |
| 系统 | Ubuntu 22.04 / 24.04 |
| 备案 | 国内节点必须备案（1~2 周）；想立刻上线选中国香港 / 新加坡节点 |
| 安全组 | 放行 22、80、443；**8080 不要对公网开放** |

装 Docker：

```bash
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER && newgrp docker     # 免 sudo
docker version                                     # 能打印 Server 版本即可
```

> **拉不到镜像（国内很常见）**：给 Docker 配镜像加速，或直接用镜像站前缀：
>
> ```bash
> sudo mkdir -p /etc/docker
> sudo tee /etc/docker/daemon.json <<'EOF'
> { "registry-mirrors": ["https://docker.m.daocloud.io"] }
> EOF
> sudo systemctl restart docker
> ```
>
> 配完 `docker pull mysql:8.0` 能拉下来即可。本项目本地验证时用的就是这条路子。

## 2. 上传代码并启动

```bash
# 服务器上
git clone <你的仓库> xiaowo && cd xiaowo
# 没有仓库就本地 scp -r 上传（务必排除 node_modules 和 dist）

cp .env.production.example .env
vim .env
```

`.env` 至少改这几项：

```ini
MYSQL_ROOT_PASSWORD=<随机串>
MYSQL_APP_PASSWORD=<随机串>
VITE_AMAP_KEY=<你的高德 Key>
WEB_PORT=127.0.0.1:8080        # 只让本机反代访问，别直接暴露
CORS_ORIGIN=https://你的域名
TRUST_PROXY=true
```

启动：

```bash
docker compose up -d --build
docker compose ps
curl http://127.0.0.1:8080/api/health
```

看到 `{"ok":true,...}` 就成功了。看日志：`docker compose logs -f web`。

## 3. 反向代理 + HTTPS

### 方案 A：Caddy（两行配置，自动签证书）

```bash
sudo apt install -y caddy
sudo vim /etc/caddy/Caddyfile
```

```caddyfile
你的域名 {
    encode zstd gzip
    reverse_proxy 127.0.0.1:8080
}
```

```bash
sudo systemctl reload caddy
```

Caddy 会自动申请 Let's Encrypt 证书并续期，前提是**域名 A 记录已指向这台服务器**、80/443 可达。

### 方案 B：Nginx

```nginx
server {
    listen 80;
    server_name 你的域名;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

证书：`sudo certbot --nginx -d 你的域名`。

> `TRUST_PROXY=true` 必须和反代一起用，否则所有请求在限流眼里都是同一个 IP，一个人点快了会让所有人被限流。

## 4. 高德地图的白名单（不做会白屏）

登录[高德开放平台](https://console.amap.com/) → 应用管理 → 找到你的 Key → 设置：

- 服务平台必须是 **Web 端 (JS API)**
- Referer 白名单加上：`https://你的域名`、`https://你的域名/*`
- 本地调试再加 `http://127.0.0.1:5173`、`http://localhost:*`

漏了这步，地图区域会报 `INVALID_USER_SCODE` 并显示空白卡片（页面其他部分正常）。

## 5. 日常运维

```bash
docker compose logs -f web            # 看应用日志
docker compose restart web            # 重启应用
docker compose down && docker compose up -d   # 改了环境变量后生效

# 更新代码
git pull
docker compose up -d --build        # 只有 web 会重建；数据库卷不动

# 备份数据库
docker compose exec db mysqldump -u root -p"$MYSQL_ROOT_PASSWORD" xiaowo > backup-$(date +%F).sql
```

改了前端内容（含高德 Key）必须 `--build`，因为前端是构建时打包的静态文件。

## 6. 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `docker compose ps` 里 web 反复重启 | 数据库还没就绪 | 等 `db` 变 healthy 再起；compose 已配 `depends_on: service_healthy`，若仍失败看 `logs web` |
| 502 Bad Gateway | 反代指向的端口不对 / web 没起来 | `curl 127.0.0.1:8080/api/health` 先确认应用活着 |
| 页面能开但地图空白 | 高德 Referer 没加，或 Key 不是 Web 端 | 见第 4 节；F12 里会看到 `INVALID_USER_SCODE` |
| 请求全变 401 | Token 过期（7 天）或 `.env` 里 `DB_*` 与容器不一致 | 重新登录；确认 compose 里 `DB_USER/DB_PASSWORD` 与 MySQL 容器一致 |
| 登录报错「演示环境的角色都被占用」 | 每个角色只允许一个账号（角色即身份） | 换一个角色注册，或用已有账号登录 |
| 快速连续出价被提示「太频繁」 | 限流 20 次/分钟（按账号） | 正常行为，等一分钟 |
| 改了 `.env` 没反应 | 环境变量在容器启动时注入 | `docker compose up -d` 重建容器 |

## 7. 和本地开发的差异

| | 本地 `npm run dev:all` | 容器 |
| --- | --- | --- |
| 前端 | Vite 热更新（5173） | 构建成静态文件，由 Express 托管（8080） |
| 数据库 | 本机 MySQL / SQLite | 容器 MySQL 8.0 |
| Redis | 本机 Docker 里的 Redis | `cache` 容器 |
| 监听地址 | `127.0.0.1` | `HOST=0.0.0.0` |
| 跨域 | 不限制 | 由 `CORS_ORIGIN` 收紧 |

本地开发方式完全没变：`npm run dev:all` 照旧，上面这些环境变量都有默认值。
