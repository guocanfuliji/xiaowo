## 二、缺陷详述

### BUG-01｜看板收入图表使用伪造数据

**现象**

房东看板「近 6 个月租金收入」柱状图的数值与账单完全无关：后端 `/api/stats/dashboard` 已返回真实的逐月金额，但页面显示的是另一套数字。

**复现**

1. 前端 `http://127.0.0.1:5180/#/dashboard`
2. 打开浏览器 Network，观察 `GET /api/stats/dashboard` 返回：

```json
"monthly": [
  { "ym": "2026-06", "label": "6月", "amount": 2800 },
  { "ym": "2026-07", "label": "7月", "amount": 2986 }
]
```

3. 页面柱状图与上述 `amount` 不一致。

**根因**

`src/views/DashboardView.vue` 在组件内自行估算月度收入，用 `Math.sin()` 造了一条假曲线，从未读取接口返回的 `monthly`：

```js
// 修复前
const monthIncome = computed(() => {
  const now = new Date()
  const rows = []
  for (let i = 5; i >= 0; i--) {
    const d = new Date(now.getFullYear(), now.getMonth() - i, 1)
    const seedVal = Math.sin(d.getMonth() + 1) * 0.12 + 1   // ← 伪造波动
    rows.push({ label: (d.getMonth() + 1) + '月', value: Math.round(income.value * seedVal) })
  }
  ...
})
```

**修复**

1. `src/stores/app.js` 新增独立 reactive 的 `stats`（不进 localStorage，避免把服务端聚合结果当本地缓存持久化）与 `loadStats()`：

```js
export const stats = reactive({
  loaded: false, houses: 0, rented: 0, rate: 0, income: 0,
  views: 0, favorites: 0, monthly: [], topHouses: []
})

export async function loadStats() {
  try {
    const d = await Api.stats()
    Object.assign(stats, d, { loaded: true })
    return d
  } catch (e) {
    stats.loaded = false
    return null          // 失败不抛错，页面回退本地推算
  }
}
```

2. 看板 `onMounted(loadStats)`，图表优先使用接口数据，接口不可用时才回退：

```js
const monthIncome = computed(() => {
  const live = stats.monthly || []
  const useLive = live.length === 6
  const rows = useLive
    ? live.map((m) => ({ label: m.label, value: Number(m.amount) || 0 }))
    : /* 离线兜底：按在租房源估算 */
})
```

3. 卡片副标题随数据来源切换，避免误导：

```html
<div class="card__desc">
  {{ stats.loaded ? '按本地账单实际到账统计' : '按当前在租房源推算，实际以账单为准' }}
</div>
```

**验证**

接口与页面数值逐月一致：2800 / 2986 / 3010 / 3045 / 2998 / 3032.6，合计 ¥17,871.6。

### BUG-02｜柱高算法退化，合计恒为 ¥0

**现象**

当在租房源为 0 时，6 根柱子高度完全相同（都是 34%），「6 个月合计」显示 ¥0，看起来像页面没加载数据。

**根因**

柱高按「最小值—最大值」归一化，常数 34 打底。当所有值相等（尤其是都为 0）时，`max - min = 0`，全部落到 34% 的保底高度：

```js
// 修复前
const max = Math.max(...rows.map((r) => r.value), 1)
const min = Math.min(...rows.map((r) => r.value))
h: Math.round(34 + ((r.value - min) / (max - min || 1)) * 66)
```

**修复**

改为以 0 为基线的比例高度，0 值不画柱；同时补上柱顶金额标签与空态文案：

```js
const max = Math.max(...rows.map((r) => r.value), 1)
h: r.value > 0 ? Math.max(6, Math.round((r.value / max) * 100)) : 0
```

```html
<div v-for="m in monthIncome" :key="m.label">
  <b>{{ m.value ? money(m.value) : '' }}</b>
  <i :style="{ height: m.h + '%' }" :title="money(m.value)"></i>
  <span>{{ m.label }}</span>
</div>
<p v-if="!monthTotal">近 6 个月还没有已出账的租金账单，签约后会自动汇总到这里。</p>
```

**验证**

6 根柱高低随金额变化；合计与逐月求和一致；无账单时显示空态文案而非等高假柱。

### BUG-03｜房源结构显示英文类型 key

**现象**

「房源结构」卡片的类型名显示为 `pineapple` / `anchor` 等英文标识，而非「菠萝屋」「船锚屋」。

**根因**

直接渲染了数据字段 `type` 的原始值，没有经过字典映射：

```html
<!-- 修复前 -->
<b style="font-weight:800">{{ t.type }}</b>
```

**修复**

引入 `HOUSE_TYPES` 字典做映射，缺失时回退原值（避免新增类型时报错）：

```js
import { HOUSE_TYPES } from '@/data/seed.js'
const typeName = (id) => (HOUSE_TYPES.find((t) => t.id === id) || {}).name || id

const byType = computed(() => {
  const map = {}
  myHouses.value.forEach((h) => { map[h.type] = (map[h.type] || 0) + 1 })
  return Object.entries(map).map(([k, v]) => ({ type: k, name: typeName(k), n: v }))
})
```

```html
<b style="font-weight:800">{{ t.name }}</b>
```

**验证**

看板显示「菠萝屋 1 套 / 贝壳屋 1 套」。

### BUG-04｜统计接口收入口径错误（后端）

**现象**

`GET /api/stats/dashboard` 返回的 `monthly` 合计了**全库所有账单**，包括与当前房东无关的租客账单。房东看到的「租金收入」实际是全平台流水。

**复现**

1. 当前用户切换到「痞老板」（`charId=plankton`，名下无在租房源，账单流水为 0）。
2. 请求接口：

```bash
curl -s http://127.0.0.1:3001/api/stats/dashboard
```

3. `rented = 0`、`income = 0`，但 `monthly` 仍返回 380 / 2814.8 / 2906.5 —— 这些全部来自**租客**账单 `B3001~B3006`（房源 `H1001`，房东是海绵宝宝）。

**根因**

`server/routes/catalog.js` 的 `billRows` 未做归属过滤：

```js
// 修复前
const billRows = rowsToObjs('bills', await db.all('SELECT * FROM bills'))
```

**修复**

先依据当前用户名下房源建立 id 集合，再过滤账单：

```js
// 只统计当前用户名下房源产生的账单
const myHouseIds = new Set(mine.map((h) => h.id))
const billRows = rowsToObjs('bills', await db.all('SELECT * FROM bills'))
  .filter((b) => myHouseIds.has(b.houseId))
```

**验证**（`charId=gary`，名下 `H1013` 可租 / `H1014` 已租）

```json
{ "houses": 2, "rented": 1, "rate": 50, "income": 2800, "views": 2010,
  "monthly": [2800, 2986, 3010, 3045, 2998, 3032.6] }
```

**优化实施记录（已落地）**

初版修复是「全表拉取 `SELECT * FROM bills` + 内存过滤」。房源规模上来后这会产生不必要的 IO，现已改为把归属判断下推到 SQL，并给 `bills.house_id` 补索引：

```sql
SELECT b.* FROM bills b
  JOIN houses h ON h.id = b.house_id
 WHERE h.owner_id = ?
```

配套改动：

| 项 | 内容 |
| --- | --- |
| 索引 | `bills` 新增 `INDEX idx_bill_house (house_id)`；`schema.mysql.sql` 与 `schema.sqlite.sql` 均已同步，存量库执行 `ALTER TABLE bills ADD INDEX idx_bill_house (house_id)` |
| 空集安全 | 用 JOIN 而非 `IN (...)`，名下无房源时不会拼出非法空列表（`IN ()`） |
| 执行计划 | `EXPLAIN` 显示 `h` 走 `idx_house_owner`（rows=2）、`b` 走 `idx_bill_house`（type=ref），无全表扫描 |

**等价性验证**：对 `gary`、`plankton`、`sandy` 三个身份分别用新旧两种写法计算逐月金额，结果完全一致（`gary` 均为 11 条、2800/2986/3010/3045/2998/3032.6）。

### BUG-05｜切换角色后昵称不同步（后端）

**现象**

把 `charId` 从 `plankton` 改回 `gary` 后，接口返回：

```json
{ "charId": "gary", "name": "痞老板" }
```

角色头像已经是小蜗，昵称却还停在「痞老板」。

**复现**

```bash
curl -X PATCH http://127.0.0.1:3001/api/user \
  -H "Content-Type: application/json" -d '{"charId":"gary"}'
```

修复前返回 `name: "痞老板"`。

**根因**

`server/routes/user.js` 的白名单允许单独更新 `charId`，但未联动角色名。前端正常切换身份时会同时提交 `{ charId, name }`，所以只在「直接调接口 / 部分客户端」时暴露。

**修复**

未显式提供 `name` 时，按 `charId` 反查角色字典补齐：

```js
// 切换角色时同步角色名，避免出现「角色是蟹老板、昵称还是痞老板」的错位
if (patch.charId !== undefined && patch.name === undefined) {
  const target = CHARS.find((c) => c.id === patch.charId)
  if (target?.name) patch.name = target.name
}
```

同时补充导入：`import { CHARS } from '../../src/data/seed.js'`（与 `server/db/init.js` 用法一致）。

**验证**

```json
{ "charId": "gary", "name": "小蜗" }
```

显式传入 `name` 时仍以调用方为准，不覆盖用户自定义昵称。

**修复**

补充一套房东侧数据，覆盖 2026-06 ~ 2026-11 六个月，使收入曲线具备真实波动：

| 类型 | 内容 |

数据同时写入 `src/data/seed.js`，新环境 `SEED_ON_INIT=true` 首次启动即可复现，不依赖手工补数据。

## 五、给后端的接口契约说明

### 1. `GET /api/stats/dashboard`

- **请求**：无变化，仍通过 `x-user-id` 头（缺省 `U1001`）识别用户。
- **响应结构**：字段完全不变。
- **语义收紧（重要）**：`monthly` 的统计范围由「全库账单」改为「当前用户名下房源的账单」。若其它端曾依赖旧的全平台口径，需要改为调用别的聚合查询，本接口不再提供全平台流水。
- **口径确认**：`monthly` 按账单 `due_date` 的**本地年月**归月（不是支付时间 `paid_at`）；金额不区分已付/未付，均为应出账金额。若业务上要区分「实收」与「应收」，需要新增字段而非改动现有字段，避免破坏兼容。

### 2. `PATCH /api/user`

- **请求**：兼容原有调用。
- **行为变化**：请求体只带 `charId`、不带 `name` 时，服务端会用 `CHARS` 字典自动补齐 `name`。
- **兼容性**：同时传 `name` 时以请求值为准，不受影响；只改 `name` 不传 `charId` 时行为不变。

### 3. 数据依赖

- 看板收入依赖 `bills.house_id` 与 `houses.owner_id` 正确关联。`houses.owner_id` 存的是**角色 id**（如 `gary`），不是用户主键 `U1001`；统计时经 `currentUserCharId()` 转换。新增写入路径务必保持这一约定，否则看板会「查不到自己的房」。

## 六、遗留事项

1. **应出账与实收未区分**：占位需求，待产品确认后再扩展字段（建议新增 `settled_amount`，不改现有 `amount` 语义）。
2. **收藏数口径**：看板「累计浏览 / 被收藏」中的收藏数基于 `favorites` 表反查，暂未区分收藏用户是否为潜在租客，后续可加去重与时间窗。
3. **本地缓存一致性**：`stats` 刻意不进 localStorage，页面每次进入都会拉取；若后续要做离线看板，需要设计缓存失效策略。

> 原「全表拉取账单」一项已在本次一并完成（见 BUG-04 优化实施记录），不再列为遗留。
